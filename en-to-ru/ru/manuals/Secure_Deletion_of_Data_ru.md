## Введение

Безопасное удаление данных не так просто, как может показаться. Когда вы удаляете файл с помощью стандартных команд операционной системы (например `rm` в UNIX или `del` в DOS или очистка корзины в Windows), операционная система НЕ удаляет сам файл — содержимое файла остаётся на вашем жёстком диске.

Большинство операционных систем просто убирают ссылки на файл, когда получают команду его удалить. Файл — который вы думаете, что навсегда исчез — остаётся на диске до тех пор, пока не будет создан другой файл поверх него (до тех пор, пока другой файл не перезапишет пространство диска, где "удалённый" файл всё ещё хранится), и даже после этого возможно восстановить данные, изучая магнитные поля на поверхности диска с помощью криминалистического оборудования.

До того как файл будет перезаписан новым файлом, все могут легко извлечь данные, например используя утилиту undelete для дисков. И даже после этого некоторые люди (например трёхбуквенные агентства) со специальным оборудованием способны восстановить ваши данные хотя бы частично.

У всех есть конфиденциальные данные, которые хотят сохранить в тайне. Например финансовые данные, личные письма, следы интернет-серфинга и т.д. Я слышал о случаях, когда люди продавали свои старые компьютеры или жёсткие диски, и покупатель восстанавливал их финансовые/бизнес-данные.

Единственный способ сделать восстановление ваших конфиденциальных данных почти невозможным — перезаписать ("wipe" или "shred") данные несколькими определёнными паттернами.

**ОСТОРОЖНО:** Использование инструментов стирания или shredding основано на очень важном допущении: что файловая система перезаписывает данные на месте. Это традиционный способ работы, но многие современные файловые системы не удовлетворяют этому допущению — например Ext4, XFS, ReiserFS и т.д.

См. http://www.die.net/doc/linux/man/man1/shred.1.html для больше информации. В этом случае решение может быть стиранием/shredding всего устройства (раздела), где хранились конфиденциальные данные — чтобы убедиться что данные действительно перезаписаны.

SystemRescue предоставляет несколько инструментов, которые способны сделать восстановление данных почти невозможным — я говорю "почти невозможно", потому что никто не может дать вам гарантию, что например NSA или FBI не могли восстановить хотя бы часть этих данных. Но используя эти инструменты это становится сложнее.

**ОСТОРОЖНО:** С другой стороны — не сможете восстановить никакие данные, удалённые этими инструментами. Будьте осторожны. Мы не будем брать ответственность за потерю данных.

Если хотите иметь абсолютную безопасность, используйте шифрование — например LOOP-AES http://loop-aes.sourceforge.net/
Зашифруйте свой домашний каталог или создайте зашифрованный раздел или контейнер для сохранения данных там.

## Основные инструменты

* **SHRED** из GNU coreutils см. https://www.gnu.org/software/coreutils/coreutils.html может использовать `shred` для безопасного удаления простых файлов, но также и целых разделов или жёстких дисков. Shred использует по умолчанию 25 перезаписывающих проходов — можно увеличить и уменьшить число перезаписывающих проходов. Поэтому shred быстрее чем wipe (см. ниже).

Например безопасное удаление всех данных на первом IDE-жёстком диске:
```bash
shred -v /dev/hda
```

* **WIPE** из Sourceforge см. http://wipe.sourceforge.net Аналогично shred можно использовать wipe для безопасного удаления простых файлов, но также и целых разделов или жёстких дисков. Wipe использует по умолчанию 35 перезаписывающих проходов. Wipe медленнее shred, потому что использует по умолчанию больше перезаписывающих проходов и поэтому более безопасен.

Например безопасное удаление Windows 98 Swap File с смонтированного (FAT) Windows раздела, используя 35 перезаписывающих проходов:
```bash
wipe -D /mnt/windows/win386.swp
```

## Другие инструменты

Есть другие инструменты на SystemRescue, которые можно использовать аналогично для перезаписи — особенно устройств, например

* **nwipe**: выбор дисков для стирания в текстовом UI; несколько алгоритмов для выбора; форк Darik's Boot and Nuke (DBAN)
* **dd**: `if=/dev/zero` или `/dev/urandom`, `of=device`
* **dd_rescue**: работает аналогично "dd"
* **badblocks**: с опцией `-w` для записей 4 статических прохода

Для больше информации посмотрите на мануалы.

## Тестирование

Чтобы увидеть как работают инструменты и проверить что все секторы — например флешки — были перезаписаны, можно использовать VCHex, виртуальный консольный hex-редактор. В нашем примере будем безопасно стирать все данные с флешки.

Сначала введите следующую команду:
```bash
shred -v -n 1 /dev/fd0
```
