## Обзор

Эта страница объясняет, как установить SystemRescue на локальный диск для запуска без необходимости использовать съёмное устройство. Эти инструкции актуальны для SystemRescue начиная с версии 6.0.0.

## Введение

Существует простой способ загрузки SystemRescue с локального диска. Это удобно, если вы часто хотите запускать SystemRescue — это быстрее и не нужно вставлять носитель перед перезагрузкой компьютера. Этот метод позволяет использовать SystemRescue так же, как версию для CD или USB. Он также позволяет загрузиться с SystemRescue, если у вас нет привода CD/DVD или разъёма USB в компьютере. Вы можете использовать другую операционную систему для установки и активации SystemRescue. Поэтому этот метод рекомендуется, если вы часто используете SystemRescue и хотите избежать необходимости вставлять устройство каждый раз.

Установка выполняется копированием файлов из носителя SystemRescue на локальную файловую систему, где установлена ваша операционная система. Этот подход не требует перераспределения диска. С помощью grub4dos можно даже установить SystemRescue на NTFS-раздел Windows. Нужно просто скопировать файлы с диска SystemRescue на существующий раздел вашего локального диска — Linux (ext4, xfs, ...) или Windows (NTFS). Таким образом вы сможете запускать SystemRescue с вашего Windows-раздела, а используя опцию `copytoram` — даже для устранения неполадок самой Windows или `ntfs-3g` для работы с файловой системой, где он установлен.

Установка состоит из двух шагов: сначала нужно скопировать основные файлы SystemRescue на раздел диска, затем настроить загрузчик. Процесс установки требует раздела с достаточным пространством для копирования файлов SystemRescue. Для установки файлов SystemRescue на Linux-раздел необходим рабочий Grub2 загрузчик.

## Первый подход: использование Grub2 с loopback.cfg

Grub2 предоставляет возможность загрузки из ISO-образа, хранящегося на локальном диске. Если разместить копию `systemrescue-x.y.z.iso` на файловой системе, которую может читать Grub2, вы сможете загрузиться с SystemRescue прямо из ISO-образа на диске. Это очень удобно, если вы часто обновляете SystemRescue и хотите загружать его напрямую через Grub2, или когда хотите настроить SystemRescue на рабочем компьютере как резервный вариант загрузки. Даже если обычная ОС станет неработоспособной, пока GRUB и соответствующий раздел жёсткого диска работают нормально, вы сможете загрузиться с SystemRescue.

Для этого SystemRescue реализует соглашение `loopback.cfg`, как 
[документировано здесь](https://supergrubdisk.org/wiki/Loopback.cfg).

#### grml-rescueboot

Самый простой способ использовать это — через пакет [grml-rescueboot](https://aur.archlinux.org/packages/grml-rescueboot), доступный для Arch через AUR и Debian/Ubuntu. Установите его, поместите ISO-образ SystemRescue в `/boot/grml/` и выполните `update-grub`. При следующем входе в меню GRUB вашей системы вы увидите новый пункт. Выберите его, и появится подменю со стандартными вариантами загрузки SystemRescue. Нажатие `Esc` вернёт к предыдущему меню.

Если у вас недостаточно места в `/boot/` для размещения ISO-образа, возможно потому он на маленьком разделе, то **grml-rescueboot** можно настроить для поиска ISO-образов в другом месте. См. параметр `ISO_LOCATION` в файле `/etc/default/grml-rescueboot`.

#### Пользовательская конфигурация

Альтернативно, если вы хорошо разбираетесь в языке конфигурации GRUB, загрузочная секция как следующая должна сработать. Убедитесь, что отредактировали строку `iso_path=` чтобы она отражала имя и расположение вашего ISO-образа SystemRescue:

```
menuentry "SystemRescue" {
  iso_path="/boot/iso/systemrescue.iso"
  export iso_path
  search --set=root --file $iso_path
  # поддержка загрузки на современных UEFI-системах
  rmmod tpm
  loopback loop $iso_path
  set root=(loop)
  # путь ниже — в ISO SystemRescue, а не на жёстком диске
  configfile /boot/grub/loopback.cfg
}
```

Обычно это добавляют в `/boot/grub/custom.cfg` или `/etc/grub.d/40_custom`.

Обратите внимание:

1. Рекомендуется удалить номер версии из имени ISO-файла, чтобы не обновлять конфигурацию GRUB каждый раз при скачивании новой версии образа.
2. Если редактируете `40_custom`, то обычно нужно выполнить `update-grub`, `grub-mkconfig -o /boot/grub/grub.cfg` или `grub2-mkconfig -o /boot/grub2/grub.cfg` (в зависимости от используемой дистрибутива Linux) после этого.
3. Возможно потребуется загрузить некоторые модули GRUB (например, `lvm`), чтобы GRUB мог читать расположение диска с ISO-образом.
4. Путь к ISO файлу относительный к содержащей его файловой системе и может не совпадать с путём, который вы видите на работающей системе. Например, если `/boot/` находится на отдельном разделе, то правильный путь должен быть `/iso/systemrescue.iso`, без префикса `/boot`. Больше информации об установке и настройке GRUB см. [здесь](https://wiki.archlinux.org/title/GRUB).

#### Шаги во время загрузки

Важно понимать основные этапы процесса загрузки для правильной настройки:
* Grub2 ищет во всех доступных разделах файловую систему, содержащую файл с именем `/boot/iso/systemrescue.iso`
* Затем путь к этой файловой системе сохраняется в переменную `root`
* ISO-файл открывается через механизм loopback
* Переменная `root` теперь указывает на устройство loopback
* Загружается и выполняется конфигурационный файл `/boot/grub/loopback.cfg`, содержащийся в SystemRescue
* Этот файл использует переменную `iso_path` для определения правильной переменной `archisolabel`
* Затем загружается и выполняется стандартная конфигурация grub `/boot/grub/grubsrcd.cfg` из SystemRescue

## Альтернативный подход: извлечение содержимого ISO-образа

Этот подход работает в Linux с загрузчиком Grub и также в Windows с Grub4dos.

Он включает копирование основных файлов SystemRescue на файловую систему диска и настройку Grub или Grub4dos для загрузки.

### Первый шаг: копирование файлов из ISO-образа на диск

Теперь смонтируйте ISO-образ через `mount` в Linux
(например: `mount -o loop systemrescue-x.y.z.iso /mnt/cdrom`) или используйте
программу типа Daemon Tools в Windows, если не записывали диск), чтобы получить основные файлы.

Нужно скопировать весь каталог `/sysresccd/` из ISO на корневую папку раздела, куда он устанавливается. Если у вас отдельный раздел `/boot`, то этот каталог должен быть скопирован в `/boot/sysresccd`. Нужно сохранить структуру каталогов как в оригинальном ISO.

### Второй шаг: обновление конфигурации загрузчика (при установке на Linux)

Теперь нужно обновить загрузчик. Этот раздел описывает, как обновить grub. Если используете NTFS-раздел, пожалуйста, прочитайте следующий раздел вместо этого.

Придётся добавить несколько строк в конфигурационный файл менеджера загрузки
(обычно находится в `/etc/grub.d/` для Grub2). Нужно адаптировать
предоставленную там конфигурацию.

Вот пример конфигурации Grub2. Создайте новый файл, например
`/etc/grub.d/25_sysresccd`, чтобы его конфигурация располагалась после
конфигурации вашей основной ОС:

```
#!/bin/sh
exec tail -n +3 $0

menuentry 'SystemRescue' {
  load_video
  insmod gzio
  insmod part_gpt
  insmod part_msdos
  insmod ext2
  search --no-floppy --label boot --set=root
  echo   'Загрузка Linux-ядра ...'
  linux  /sysresccd/boot/x86_64/vmlinuz archisobasedir=sysresccd archisolabel=boot copytoram setkmap=us
  echo   'Загрузка initramfs ...'
  initrd /sysresccd/boot/x86_64/sysresccd.img
}
```

После создания файла конфигурации обычно нужно выполнить команду
`grub-mkconfig -o /boot/grub/grub.cfg` для генерации финальной grub-конфигурации. Убедитесь, что финальная конфигурация grub содержит ожидаемую секцию SystemRescue перед перезагрузкой.

### Второй шаг: обновление менеджера загрузки grub4dos (при установке на Windows)

Теперь нужно обновить ваш менеджер загрузки через grub4dos — это порт grub для Windows. Этот раздел описывает установку grub4dos, если вы установили файлы SystemRescue на NTFS-раздел под Windows. Если используете Linux-раздел, прочитайте предыдущий раздел вместо этого.

Одно из самых интересных применений установки sysresccd ntfs — устранение неполадок Windows при проблемах. Таким образом можно смонтировать Windows-раздел через ntfs-3g и починить Windows (заменить резервную копию реестра, ...). Единственная проблема — нельзя монтировать Windows-диск с чтением/записью через ntfs-3g, потому что он уже был монтирован только на чтение во время загрузки. Решение этой проблемы — использовать опцию `copytoram` при загрузке. Когда эта опция включена, sysresccd кэширует свои файлы (найдённые на ntfs-диске) в памяти во время загрузки, и ntfs-диск размонтируется. Так можно снова его смонтировать через ntfs-3g. Нужно добавить `copytoram` в опции загрузки `menu.lst`, если хотите монтировать свой Windows-диск с помощью ntfs-3g после загрузки с самого ntfs-диска.

Установка действительно проста. В этом мини-руководстве предполагаю, что Windows установлена на NTFS-диске (Disk-C), и вы скопировали основные файлы SystemRescue в `C:\sysresccd`.

Нужно скачать grub4dos, извлечь ZIP-архив во временную директорию и
скопировать `grldr` в `C:\`. Эта установка тестировалась с файлом `grldr`,
предоставленным с `grub4dos-0.4.3-2007-08-27.zip`, но должна работать с любой актуальной версией.

Вместе с `grldr` нужно скопировать `grldr.mbr` (часть архива)
в корень раздела загрузки Windows. Затем нужно выполнить несколько команд в командной строке (запустите `cmd.exe` от имени администратора).

В окне командной строки (`C:>` — условное название для приглашения cmd) выполните следующее:

```
C:> bcdedit /create /d "SystemRescue [GRUB4DOS]" /application bootsector
```

Получите в ответ загрузочный пункт `{id}` — используйте его (скопировать/вставить или ввести вручную) в следующих шагах:

```
C:> bcdedit /set {id} device boot
C:> bcdedit /set {id} path \grldr.mbr
C:> bcdedit /displayorder {id} /addlast
```

Нужно создать `C:\menu.lst` — это конфигурационный файл `grub4dos`. Вот пример. Он соответствует 64-битной архитектуре (amd64/x86_64). Если используете 32-битную версию, замените все вхождения `x86_64` на `i686`:

```
# Это примерный файл menu.lst для SystemRescue
title    SystemRescue с NTFS-диска
root     (hd0,0)
kernel   /sysresccd/boot/x86_64/vmlinuz archisobasedir=sysresccd archisolabel=windows copytoram setkmap=us
initrd   /sysresccd/boot/x86_64/sysresccd.img
```

В `menu.lst` нужно обновить `archisolabel`, чтобы он соответствовал метке NTFS-файловой системы, содержащей `sysresccd`, и также следует обновить параметр `setkmap` так, чтобы код соответствовал вашей конфигурации клавиатуры. В этом примере файлы находятся на NTFS-разделе, который является первым разделом первого жёсткого диска. Тогда имя устройства grub — `(hd0,0)`. Для первого раздела второго жёсткого диска это будет `(hd1,0)`, `(hd0,1)` для второго раздела первого жёсткого диска и т.д. Нужно заменить `root (hd0,0)` на имя grub вашего NTFS-раздела.
