# Установка дополнительных программных пакетов с помощью pacman

Чтобы сохранить его лёгким и быстрым SystemRescue приходит только с софтом который напрямую связан с целями диагностики и исправления системных проблем. Но дополнительные программы могут легко быть установлены из репозиториев предоставляемых Arch Linux.

## pacman Basics

pacman — это программа используемая для установки и управления пакетами. Перед использованием его вам нужно скачать копию базы данных репозитория пакетов чтобы pacman знал какие пакеты доступны и как они связаны друг с другом.

Это может быть сделано следующим образом (требуется интернет доступ): `pacman -Sy`

После этого вы можете скачать и установить новые пакеты следующим образом: `pacman -S <package name>`

Помните что это может потребовать много места в writable слое (хранится в памяти по умолчанию) чтобы скачать и установить дополнительные пакеты. Так что это может не сработать если запрошено слишком много пакетов.

## Поиск

Когда вы не знаете точное имя пакета который хотите установить вы можете искать текстовые части в имени пакета и описании: `pacman -Ss <search string>`

Как только вы знаете имя пакета вы можете получить больше информации о не установленном пакете следующим образом: `pacman -Si <package name>`

Вы также можете искать пакеты которые предоставляют заданный filename. Вам нужно сначала скачать отдельный файл базы данных: `pacman -Fy` После этого вы можете искать пакеты по filename: `pacman -F <filename>`

## Snapshot vs. Rolling

SystemRescue начиная с версии 8.07 по умолчанию обращается к репозиториям в состоянии замороженном на момент выпуска SystemRescue. Это делается чтобы предотвратить огромные загрузки из-за зависимостей и конфликтов. Это называется snapshot конфигурацией pacman. Она реализована используя [Arch Linux Archive](https://wiki.archlinux.org/title/Arch_Linux_Archive) от даты выпуска.

Arch Linux наоборот имеет rolling release схему где даже старые установки всегда получают новейшие пакеты. Это также может быть доступно из SystemRescue активируя rolling конфигурацию pacman.

## Переключение на Rolling конфигурацию

Обе конфигурационные версии pacman установлены параллельно. Вы можете переключиться на rolling вариант на per-command основе с `--config` параметром: `pacman --config=/etc/pacman-rolling.conf <pacman command>`

Обе конфигурации имеют отдельные удалённые репозиторий базы данных. Так что вам нужно скачать их для rolling config перед тем как использовать его: `pacman --config=/etc/pacman-rolling.conf -Sy`

Вы также можете навсегда переключиться на rolling конфигурацию указав symlink `/etc/pacman.conf` на `/etc/pacman-rolling.conf`.

Однако будьте особенно осторожны когда используете rolling конфигурацию. Вы можете случайно render вашу систему нестабильной например обновив Linux kernel пакет. Тогда модули не будут соответствовать запущенному kernel больше. Обновления типа этого не обязательно должны быть сделаны намеренно но могут прийти через зависимость от установки или обновления другого пакета.

## Репозитории

Arch Linux предоставляет несколько разных репозиториев. SystemRescue только имеет официальные репозитории `core`, `extra` и `community` preconfigured.

Вы можете конфигурировать больше [Official](https://wiki.archlinux.org/title/Official_repositories) и [Unofficial](https://wiki.archlinux.org/title/Unofficial_user_repositories) репозиториев. Но будьте осведомлены что другие репозитории часто будут конфликтовать с дефолтной snapshot конфигурацией.

Вы можете искать пакеты здесь: [https://archlinux.org/packages/](https://archlinux.org/packages/)

Если какой-то софт не упакован ни в одном из этих репозиториев он может быть доступен в [Arch User Repository (AUR)](/manual/Installing_packages_from_AUR/).

## Сигнатурный ключ истечение

Arch Linux (и thus SystemRescue) использует GnuPG и web of trust чтобы подписывать пакеты и проверять пакет аутентичность. Некоторые из использованных ключей имеют определённую дату истечения. Это может привести к проблемам когда используют snapshot конфигурацию и ключ используемый для подписи пакета или в trust path истёк с момента выпуска вашей версии SystemRescue.

Сообщение об ошибке будет выглядеть следующим образом:

```
error: foobar: signature from "John Doe <[email protected]>" is unknown trust
:: File /var/cache/pacman/pkg/foobar-1.2-3-x86_64.pkg.tar.zst is corrupted (invalid or corrupted package (PGP signature)).
Do you want to delete it? [Y/n] 
```

SystemRescue содержит wrapper названный `pacman-faketime` начиная с версии 9.06. Это может быть вызвано вместо `pacman` и заставляет pacman думать что текущая дата — это оригинальная дата выпуска вашей версии SystemRescue. Поскольку ключ не истёк в ту дату проверка ключа проходит.

Альтернативное решение этой проблемы — обновить trust database SystemRescue до текущего из rolling Arch Linux release:

```
pacman --config=/etc/pacman-rolling.conf -Sy archlinux-keyring
```

Это рекомендуемый способ когда используете rolling конфигурацию. Но будьте осведомлены что использование `pacman-faketime` скорее всего не будет работать как ожидается и некоторые пакеты из snapshot config могут всегда показывать signature ошибки.

С момента изменённой даты также влияет на validity период SSL/TLS сертификатов используемых для загрузки `pacman-snapshot.conf` конфигурирован чтобы вызвать curl wrapped в faketime снова чтобы восстановить оригинальную дату. Хотя этот подход решает проблему faketime показывает warning сообщение на каждой загрузке:

```
faketime: You appear to be running faketime within a libfaketime environment. Proceeding, but check for unexpected results...
```

Также есть sledgehammer решение: установите `SigLevel = Never` в `/etc/pacman-snapshot.conf`. Это решает проблему но также уничтожает любые надежды блокировать tampered пакеты. Так что это не рекомендуется.
