## Обзор autorun

**Функция autorun** позволяет автоматически запускать скрипты или бинарные программы при старте системы. Каждый скрипт autorun может управлять задачей. Например, можно создать скрипт резервного копирования, который делает резервную копию базы данных, другой для очистки системы и т.д.

По умолчанию скрипт(ы) autorun могут быть скопированы в директорию `autorun` образа ISO или загрузочного устройства, вне файла squashfs-образа, но доступны и другие источники: локальная файловая система, сетевое общее место, HTTP/HTTPS-сервер.

## Методы конфигурации

SystemRescue предлагает два метода для конфигурирования программ autorun:

- **Основанный на имени**. Программы с именем файла начинающимся с `autorun` в наборе мест загружаются и выполняются. Это старый стиль конфигурирования autorun.
- **Основанный на YAML-конфигурации**. Конфигурационный файл содержит пути, URL и параметры столько программ autorun, сколько необходимо. Это новый стиль конфигурирования autorun, доступный начиная SystemRescue версии 9.05.

Оба метода полностью поддерживаются и планируются остаться доступными в будущих релизах.

## Конфигурирование autorun с помощью YAML

Синтаксис:

```
---
autorun:
    exec:
        200:
            url: "http://web-server/adminscripts/some-script"
            parameters: 
                - "foo"
                - "bar"
            shell: false
            wait: always
            waitmode: 15
            on_error: break
        300:
            path: "rclone"
            parameters: 
                - "copy"
                - "myserver:/scripts/"
                - "/root"
            wait: on_error
            on_error: break
```

Конфигурация делается через записи в [YAML-конфигурации](/manual/Configuring_SystemRescue/) используя записи `exec` в области `autorun`. Ключи в Mapping/словаре `exec` (`200` и `300` в примере выше) — это имена для каждой программы autorun. Программы выполняются в лексикографическом порядке этих имён.
