## Загрузка со съёмного устройства

Для загрузки с CD-ROM или USB-устройства убедитесь, что firmware компьютера (настройки BIOS или UEFI) конфигурирован для загрузки с правильного устройства и приоритет установлен верно.

Для запуска SystemRescue вставьте диск или USB-накопитель в привод, включите или перезагрузите компьютер, или нажмите клавишу для выбора альтернативного загрузочного устройства при старте.

## Опции командной строки загрузки

В загрузчике можно нажать TAB (syslinux, используется для классической загрузки BIOS) или "e" (grub, используется для загрузки UEFI), чтобы отредактировать командную строку загрузки текущего выбранного загрузочного пункта. Затем можно добавить опции, перечисленные ниже.

### Доступные в командной строке и YAML-конфигурации

Большинство опций доступны как в командной строке загрузки, так и в 
[YAML-конфигурации](/manual/Configuring_SystemRescue/) в области `global`. Опции в командной строке загрузки имеют более высокий приоритет, чем в YAML.

Следующие опции поддерживаются в командной строке загрузки и в YAML:

* **setkmap=xx** определяет систему для настройки раскладки клавиатуры, где `xx` соответствует коду карты клавиатуры. Например `setkmap=de` настроит немецкую раскладку клавиатуры во время загрузки. Также можно задать раскладку, запустив команду типа `setkmap de` из оболочки после загрузки, и в терминале работающего SystemRescue можно выполнить `setkmap` без параметров для получения списка всех поддерживаемых карт клавиатуры.
* **copytoram** заставляет SystemRescue полностью загрузиться в память. Это соответствует опции `docache` в предыдущих версиях. Медленнее запуск, но после завершения система будет более отзывчивой и не потребуется оригинальное устройство для работы. Это значит можно фактически работать с устройством, где установлен SystemRescue. Требуется 2 ГБ памяти для кэширования системы.
* **checksum** вызовет проверку контрольной суммы squashfs во время загрузки, чтобы знать, если файл повреждён. Используйте эту опцию загрузки, если получаете неожиданные ошибки при загрузке SystemRescue.
* **rootpass=password123**: устанавливает пароль root для системы, работающей с livecd, в `password123`. Так можно подключаться из сети и ssh на livecd и аутентифицироваться с помощью этого пароля. По соображениям безопасности рекомендуется использовать альтернативную опцию `rootcryptpass` вместо `rootpass`, чтобы пароль не был виден как чистый текст.
* **rootcryptpass=xxxx**: устанавливает пароль root для системы, работающей на livecd, чтобы можно было подключаться к системе удалённо через ssh и использовать пароль для аутентификации на livecd. Пароль должен быть зашифрован с помощью команды `mkpasswd`. Программа mkpasswd доступна в большинстве дистрибутивов Linux, часто входит в пакет `whois`. Нужно предоставить весь вывод mkpasswd в `rootcryptpass=`, включая префикс `$`. Зашифрованный пароль содержит знаки доллара, поэтому проверьте, требует ли ваш загрузчик их экранирования. Если сомневаетесь, посмотрите на `/proc/cmdline` загруженного SystemRescue.
* **nofirewall** останавливает службы iptables и ip6table, которые включены по умолчанию для блокировки входящих соединений. Нужно использовать эту опцию, если нужно устанавливать соединения с системой, работающей SystemRescue, извне (например, подключения к sshd). Эта опция появилась в SystemRescue-6.0.4.
* **rootshell=/bin/myshell** использует альтернативную оболочку, такую как /bin/zsh вместо /bin/bash. Эта опция появилась в SystemRescue-6.1.1.
* **cow_label=xxxx** устанавливает метку файловой системы, где файлы upperdir/workdir для overlayfs должны храниться. По умолчанию эта опция не установлена и изменения на файлах SystemRescue теряются после перезагрузки. Иначе говоря можно использовать Linux-файловую систему для сохранения всех изменений, сделанных на SystemRescue при работе, таких как новые закладки в Firefox, конфигурационные файлы приложений и т.д. Нужно предоставить метку файловой системы, которая должна использоваться для хранения этих изменений. Все эти изменения будут изолированы в директории с префиксом `persistent`, если не переопределите это через `cow_directory`.
* **cow_directory=xxxx** имя директории, где хранить изменения на системе. Обязательно нужно указать cow-устройство для этого изменения.
* **loadsrm=y** загружает все модули SRM, находящиеся на загрузочном устройстве
* **noautologin** не выполняет автоматический вход в консоль. Используйте эту опцию, если планируете использовать SystemRescue для выполнения автоматических задач для удалённого подключения и хотите предотвратить использование системы локальными пользователями из консоли. Эта опция появилась в SystemRescue-8.06.
