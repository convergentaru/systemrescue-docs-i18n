# Конфигурация SystemRescue: область действия `sysconfig`

Эта глава объясняет опции, доступные в области действия `sysconfig` файлов yaml конфигурации System Rescue. Перейдите туда для деталей о том, где разместить файлы yaml и как они интерпретируются.

## Синтаксис

```yaml
---
sysconfig:
    authorized_keys:
        "[email protected]": "ssh-rsa AAAAB3NzaC1...kQoVPcn3jpgywi/twXcOw=="
        "[email protected]": "no-port-forwarding ssh-rsa ZDWo0UmISKEn...dAq33PUQh"
        "[email protected]": "cert-authority,principals=\"bob,joe\" ssh-rsa AAAAB3NzaC1y...Zhk0="

    bash_history:
        100: "setkmap"
        200: "reverse_ssh support.example.com 1234"

    bookmarks:
        0100:
            title: "SystemRescue"
            url: "https://www.system-rescue.org/"
        0200:
            title: "Arch Linux Package Search"
            url: "https://archlinux.org/packages/"

    ca-trust:
        example-ca: |
            -----BEGIN CERTIFICATE-----
            MIIDlTCCAn2gAwIBAgIUbB4K7H53E3spHfMtSb0To+Fyb3wwDQYJKoZIhvcNAQEL
            BQAwWjELMAkGA1UEBhMCWFgxFTATBgNVBAcMDERlZmF1bHQgQ2l0eTEcMBoGA1UE
            [...]
            VtbLuXNBNjfcAk1xqTb1j9dMeHDZKV4Imr0W3qfsHnWFqihxGyKJ79Qb2bL1Kquc
            vgI/6+yHyDlw
            -----END CERTIFICATE-----

    hosts:
        "192.168.1.1": "example.net.lan"
        "192.168.1.10": "foo.net.lan foo"

    rclone:
        config:
            arch-linux-archive:
                type: "http"
                url: "https://archive.archlinux.org/"

            my-nas:
                type: "webdav"
                url: "https://my-nas.local"
                vendor: "other"
                user: "my-login"
                pass: "9JbSJzgcQXsnV2dkzzhBR3za1e_rqixvKKp6"

    ssh_known_hosts:
        myhost.example.org: "ssh-ed25519 AAAAC3NzaC1l...JJTO48B"
        "@cert-authority *.mydomain.org": "ssh-rsa AAAAB3NzaC1y...Zhk0="

    sysctl:
        net.ipv4.ip_forward: "1"
        net.ipv4.conf.all.arp_filter: "1"

    timezone: "Europe/Berlin"
    
    display_scale: "disabled"
```

## SSH authorized_keys

Разрешает конфигурировать доверенные публичные ключи, которым разрешено войти как пользователь `root` через SSH. Эти ключи добавляются к `/root/.ssh/authorized_keys`.

Эта опция структурирована как Mapping/словарь с полем «comment» строки authorized_keys SSH в качестве ключа и началом записи до комментария в качестве значения. Поскольку поле «comment» часто используется для указания имени пользователя или адреса электронной почты владельца, записи упорядочиваются по этим именам владельцев. Если файл уже содержит запись с данным «comment», она не добавляется повторно.

Вы можете использовать дополнительные опции для ключа, как документировано sshd, добавив их в начало типа ключа. См. например опцию `no-port-forwarding` в примере выше.

Вы можете доверять подписям от SSH Certification Authority (CA), добавив публичный ключ CA с опцией `cert-authority`. Опция `principals=` позволяет контролировать, какие имена владельцев сертификатов («principals», установленные с опцией `-n` при создании сертификата) разрешены для входа. Опция principals не имеет ничего общего с именами локальных учётных записей (например «root»).

## Bookmarks

Эта опция позволяет конфигурировать закладки для установленного браузера Firefox. Это реализовано через файл `policies.json` Firefox.

Эта опция структурирована как два уровня Mapping/словарей. Ключ первого уровня используется для лексикографического упорядочивания записей. Каждая запись должна иметь ключи `title` и `url`.

Когда файл `policies.json` уже содержит запись с заданным `title`, закладка не будет добавлена повторно. Firefox был замечен удаляющим записи с дублирующими URL.

## Certification Authority (CA) trust

Если вы ведёте одну или несколько локальных Certification Authorities (CA), вы можете добавить их как якоря доверия SystemRescue, перечислив их в разделе `ca-trust` файла yaml. Вы должны дать каждой CA индивидуальное имя внутри раздела `ca-trust`. Это имя будет использоваться как имя файла внутри директории `/etc/ca-certificates/trust-source/anchors/`.

Конфигурируемые CA будут добавлены к якорям доверия по умолчанию SystemRescue, которые выводятся из списка CA, используемого Mozilla.

Эти CA в формате X.509 и используются преимущественно для TLS. Не путать с CA для SSH.

## Timezone

Разрешает конфигурировать часовой пояс для использования. Принимает имя часового пояса как определено в [IANA Time Zone Database](https://www.iana.org/time-zones), которая используется большинством дистрибутивов Linux. По умолчанию «UTC».

## Sysctl

Разрешает кастомизировать параметры ядра через интерфейс `sysctl`. Эта опция структурирована как Mapping/словарь с ключом, который является переменной sysctl, а значением — значение для установки. Использование паттерн опции программы `sysctl` **не** поддерживается, вы должны использовать явные имена переменных.

Рекомендуется использовать строки для значений в файле yaml конфигурации, потому что числовые значения могут быть конвертированы в floating point во время слияния конфигурации. Ядро отклонит floating point значения для большинства переменных.

## rclone

Разрешает конфигурировать [rclone](https://rclone.org/). Записи ниже ключа `sysconfig.rclone.config` записываются как секции в файл `/root/.config/rclone/rclone.conf`. Для создания секций в правильном формате рекомендуется использовать команду `rclone config` для конфигурации rclone, а затем перенести данные из файла `rclone.conf` в yaml конфигурацию.

Обратите внимание, что rclone требует все пароли закодировать в проприетарной, легко обратимой схеме. SystemRescue просто скопирует пароли и не будет кодировать или изменять их, поэтому yaml конфигурация должна содержать их уже в закодированном формате. Если злоумышленник может прочитать yaml конфигурацию, эта защита не защитит пароли.

## bash_history

Разрешает преконфигурировать общие команды в оболочке bash так, что они могут быть доступны просто нажав клавишу вверх или найдены с ctrl+r. Ключ Mapping/dict используется для лексикографического обратного упорядочивания записей. Обратное упорядочивание означает, что самый низкий ключ появится первым при нажатии клавиши вверх.

По умолчанию команда `setkmap` вставляется в bash_history с ключом `100` для возможности изменения раскладки клавиатуры без необходимости печатать на возможно иностранной клавиатуре. Это упомянуто в тексте приветствия, который показывается при входе в систему. Помните, что текст приветствия не адаптируется автоматически, когда вы заменяете `setkmap` другой командой.

## hosts

Разрешает вручную конфигурировать сопоставления hostname/IP, которые имеют приоритет над DNS lookups через файл /etc/hosts. Ключ Mapping/dict — это IP (IPv4 или IPv6), а значение — hostname и, опционально, alias имена для него.

## ssh_known_hosts

Разрешает конфигурировать известные ключи хостов при создании исходящих SSH соединений. Эти ключи добавляются к `/etc/ssh/ssh_known_hosts`.

Эта опция структурирована как Mapping/словарь с полями «marker» и «hostnames» (разделёнными пробелом) строки ssh_known_hosts SSH в качестве ключа, а полями «keytype», «base64-encoded key» и «comment» в качестве значения. Если файл уже содержит запись с данной записью, она не добавляется повторно.

Вы можете доверять подписям ключей хоста от SSH Certification Authority (CA), добавив публичный ключ CA с маркером `@cert-authority`. После этого маркера и пробела вы можете использовать wildcards для указания hostnames, для которых подписи CA доверяются, или использовать `*` для доверия всему, что CA подписало.

## display_scale

Всё слишком маленькое для использования в Xorg/XFCE по умолчанию на экранах с очень высоким разрешением (также HiDPI), таких как экран с разрешением 3840x2160. Коэффициент масштабирования может быть применён вручную из настроек XFCE display, чтобы всё выглядело намного больше на таких экранах, но это требует ручного вмешательства каждый раз, когда пользователь использует систему, так как конфигурация не постоянная. Вот почему был разработан скрипт для автоматического применения коэффициента масштабирования при запуске графической среды. Скрипт расположен в `/usr/bin/configure-display` и выполняется автоматически при запуске Xorg благодаря `/etc/xdg/autostart/configure-display.desktop`. Поведение этого скрипта контролируется значением `display_scale` в файле yaml конфигурации. Значение по умолчанию этой опции — `disabled`, что означает, что скрипт ничего не будет делать. Это поведение по умолчанию для предотвращения неблагоприятного влияния скрипта до тех пор, пока оно не будет хорошо протестировано. Вам нужно установить эту опцию либо на `auto`, либо на число такое как `1.5` или `2.0`, чтобы скрипт фактически применял коэффициент масштабирования при запуске Xorg. Если вы используете `auto`, скрипт автоматически определит, какой должен быть коэффициент масштабирования, основываясь на разрешении экрана (в пикселях) и размере (в миллиметрах). Это поведение полезно в случае, если вы хотите использовать тот же носитель System-Rescue с той же конфигурацией на разных компьютерах, которые не все имеют одинаковые типы экранов. Вы также можете использовать эту опцию с числами такими как `1.5`, `2.0` или `2.5`, чтобы применить конкретный коэффициент масштабирования. Число должно быть между `1.0` и `5.0`, иначе оно будет считаться невалидным. Скрипт использует вывод `xrandr --query` для получения информации о экранах, и записывает логи в `/var/log/configure-display.log` на случай если вам нужно troubleshoot проблемы.
