# Позвольте собственным программам взять под контроль виртуальный терминал для пользовательского взаимодействия: autoterminal

## Обзор Autoterminal

Linux предоставляет несколько виртуальных терминалов на консоли, которые можно переключать с ALT+F<n>. По умолчанию 6 виртуальных терминалов (ALT+F1 до ALT+F6) создаются и используются для getty с автоматическим входом root. См. [boot option](/manual/Booting_SystemRescue/) `noautologin` и опцию `NAutoVTs` в `/etc/systemd/logind.conf` если хотите изменить эти дефолты.

Autoterminal позволяет заменить getty и shell на виртуальном терминале программой по вашему выбору.

## Конфигурация

Конфигурация делается исключительно через записи в [YAML configuration](/manual/Configuring_SystemRescue/) используя область действия `autoterminal`. Имя устройства терминала (`tty<n>`) — это ключ, а значение — команда для выполнения:

```yaml
---
autoterminal:
    tty2: "/usr/bin/setkmap"
    tty3: "/root/myscript \"parameter one\""
    tty4: "/usr/bin/tmux"
    tty8: "/usr/bin/journalctl -f"
```

Если вы хотите использовать параметры команды которые включают пробелы или кавычки, вы должны экранировать их обратным слэшем (`\`). Заданная команда записывается в systemd unit file без изменений, поэтому смотрите systemd документацию для деталей.

## Порядок выполнения

Autoterminals запускаются только после того как [autorun](/manual/Run_your_own_scripts_with_autorun/) завершён. Это позволяет использовать autorun для подготовки данных или загрузки программ используемых для autoterminal с удалённого сервера.

Systemd по умолчанию задерживает старт getty на 5 секунд (`Type=idle`). Это предотвращает любой консольный вывод других программ запутать терминал. Autoterminal всегда напрямую запускает запрограммированные программы вместо этого (`Type=simple`). Это для прямого разрешения пользовательского взаимодействия без любого времени ожидания.

## Возможные конфликты

По умолчанию systemd создаёт 6 виртуальных терминалов. Но Linux позволяет до 63 виртуальных терминалов, хотя обычные клавиатуры не имеют более 12 F-Keys для доступа к ним. Вы можете использовать все виртуальные терминалы которые вы можетедоступить с вашей клавиатурой с autoterminal. Для каждого запрограммированного autoterminal дефолтные терминалы запрограммированные в systemd будут masked чтобы предотвратить конфликты.

Когда вы используете [boot option](/manual/Booting_SystemRescue/) `dostartx`, вы должны оставить `tty1` на его дефолтной конфигурации, иначе `dostartx` не будет работать. Вы всё ещё можете вручную выполнить `startx` на других терминалах когда `tty1` используется autoterminal.

## Serial terminals

Вы также можете использовать autoterminal на [serial consoles](/manual/Booting_on_a_serial_console/). Поскольку serial устройства требуют другую конфигурацию, autoterminal должен знать что он используется с serial консолью. Это делается префиксом имени терминала `serial:`:

```yaml
---
autoterminal:
    "serial:ttyS0": "/usr/bin/tmux"
```

Autoterminal не конфигурирует serial устройство никаким образом, как установка baud rates, stop bits и подобного. Это обычно делается на kernel boot command line когда используется serial устройство как serial консоль, например так: `console=ttyS0,115200n8`. Но это также может быть сделано отдельно, например с [autorun](/manual/Run_your_own_scripts_with_autorun/).

## Примеры использования

* Вы можете запустить **tmux** на виртуальном терминале. Это позволит вам (среди других вещей) прокрутить назад в терминале снова, функция которая была удалена с виртуальных терминалов с kernel 5.9 из-за багов.
* Вы можете создать небольшие **интерактивные текстовые меню**. SystemRescue приходит с программой `dialog` и [Python library](https://pythondialog.sourceforge.io/) для неё, которая позволяет создавать такие меню легко.
* Показывайте последние сообщения в **journal** на виртуальном терминале, чтобы видеть провалы и предупреждения. Используйте `journalctl -f` чтобы включить follow-mode.
